# Интерфейс ERP: устройство и правила

Фронтенд написан на чистых **HTML / CSS / JavaScript**: без фреймворков,
без сборки, без внешних CDN. Разложен по стандартной структуре Django.

```
app/
├── templates/
│   └── index.html            разметка: экран входа, сайдбар, топбар,
│                             слои модалок, тостов и AI-панели
└── static/
    ├── css/
    │   ├── tokens.css        дизайн-токены: палитра, тени, радиусы, отступы
    │   ├── base.css          сброс, типографика, утилиты, печать
    │   ├── layout.css        каркас, адаптив, экран входа
    │   └── components.css    кнопки, формы, таблицы, карточки, канбан, тосты
    ├── js/
    │   ├── core/
    │   │   ├── utils.js      DOM-хелперы, деньги, даты, CSV, ГПСЧ
    │   │   ├── icons.js      инлайновый SVG-набор (~70 иконок)
    │   │   ├── config.js     режим работы: api или demo
    │   │   ├── api.js        клиент REST API: JWT, обновление токена, CRUD
    │   │   ├── i18n.js       русский / кыргызский / английский
    │   │   ├── store.js      слой данных: сервер или localStorage
    │   │   ├── seed.js       демо-данные для автономного режима
    │   │   ├── auth.js       вход, роли, проверки прав
    │   │   ├── router.js     hash-роутер с проверкой доступа
    │   │   ├── charts.js     SVG-графики: линия, столбцы, кольцо, спарклайн
    │   │   ├── ui.js         компоненты: таблица, форма, модалка, вкладки…
    │   │   ├── helpers.js    прикладная логика: долги, проводки, автопроверка
    │   │   └── xlsx.js       обмен с Excel: выгрузка отчётов, загрузка выписок
    │   ├── modules/          11 файлов — 45 экранов системы
    │   └── app.js            оболочка: навигация, поиск, уведомления, AI
    └── img/                  favicon.svg, logo.svg
```

Ни одного `import`, `require`, `package.json` или `node_modules`: скрипты
подключаются обычными `<script>` и общаются через пространство имён `App`.

## Как это работает

**Одна страница, навигация на клиенте.** Django отдаёт `templates/index.html`,
дальнейшие переходы выполняет hash-роутер (`#/documents`, `#/sales`).
Маршрут проверяет права: если у роли нет доступа к модулю, вместо экрана
показывается «Доступ запрещён».

**Конфигурация из шаблона.** Представление `apps/web/views.py` передаёт
настройки через `json_script`:

```html
{{ app_config|json_script:"app-config" }}
```

`config.js` читает тег `#app-config` и включает режим `api`. Если тега нет
(страница открыта без Django), включается автономный демо-режим на `localStorage` —
он нужен, чтобы показать интерфейс без сервера.

**Данные.** `store.js` загружает всё одним запросом `GET /api/bootstrap/`
и держит в памяти, поэтому чтение (`all`, `get`, `query`) синхронное и модули
не работают с промисами. Запись применяется локально сразу и уходит на сервер;
если сервер отказал — правка откатывается и показывается уведомление.

| Метод `Store`             | HTTP-запрос                      |
|---------------------------|----------------------------------|
| `initFromServer(payload)` | `GET    /api/bootstrap/`         |
| `insert(name, obj)`       | `POST   /api/<name>/`            |
| `update(name, id, patch)` | `PATCH  /api/<name>/<id>/`       |
| `remove(name, id)`        | `DELETE /api/<name>/<id>/`       |
| `Auth.login(login, pass)` | `POST   /api/token/` (SimpleJWT) |

Журнал аудита в режиме `api` пишет сервер, поэтому клиентский `logAction` молчит.
Настройки оформления (тема, язык, плотность) всегда хранятся локально — их меняет
любой пользователь, даже без прав на раздел настроек.

## Как добавить экран

1. В нужном файле `static/js/modules/*.js` написать функцию, возвращающую
   разметку через `UI.page({...})`.
2. Зарегистрировать маршрут:
   ```js
   App.Router.add('my-screen', { title: 'Мой раздел', module: 'sales', render: myScreen });
   ```
3. Добавить пункт в `NAV` в `static/js/app.js` — он появится в меню только
   у ролей, у которых есть доступ к указанному модулю.

Новая коллекция данных — одна строка в реестре `app/apps/api/registry.py`:
модель, модуль для чтения и, при необходимости, модуль для записи.

## Компоненты

Экраны собираются из готовых кирпичиков `App.UI`, поэтому все разделы выглядят
одинаково и ведут себя предсказуемо:

- `UI.page` — заголовок, подзаголовок, кнопки действий;
- `UI.statGrid` — ряд KPI-плиток;
- `UI.table` — таблица с поиском, фильтрами, сортировкой, пагинацией,
  экспортом в CSV, итогами и действиями строк;
- `UI.form` / `UI.formModal` — формы с валидацией и 12-колоночной сеткой;
- `UI.modal`, `UI.confirm`, `UI.detailModal`, `UI.toast`;
- `UI.tabs`, `UI.timeline`, `UI.kv`, `UI.meter`, `UI.dropzone`;
- `Charts.line / bars / donut / hbars / spark` — графики на чистом SVG.

Состояния предусмотрены на уровне компонентов: загрузка, пусто, ошибка,
нет прав, «ничего не найдено» по фильтру.

## Палитра

Все цвета объявлены в `static/css/tokens.css`; компоненты используют только
переменные, поэтому смена палитры — правка одного файла.

| Цвет | Код | Роль |
|---|---|---|
| Carbon Black | `#0D0F12` | фон тёмной темы |
| Concrete Grey | `#2A2E33` | нейтральные поверхности |
| Architectural Grey | `#5A6169` | вторичный текст, разделители |
| Deep Ocean Blue | `#0B2A4A` | фирменный синий: сайдбар, действия в светлой теме |
| Copper Gold | `#C18A4A` | акцент: кнопки, активные пункты, первый ряд графиков |
| Titanium Silver | `#B7BDC6` | светлый текст на тёмном |
| Sand White | `#E6E1D6` | тёплый фон светлой темы |

Тёмная тема — карбон с медью, светлая — песочный фон с глубоким синим.
Текст на акцентных плашках задаётся переменными `--on-brand` / `--on-accent`:
на меди он тёмный, на синем — светлый, поэтому контраст держится в обеих темах.

## Правила разработки

- **Никакого хардкода цветов** — только `var(--…)` из `tokens.css`.
- **Модули не трогают DOM напрямую** — только через `App.UI` и `App.Charts`.
- **Данные только через `App.Store`** — модули не знают про сеть и localStorage.
- **Широкие таблицы скроллятся внутри карточки**, страница по горизонтали не едет.
- **Доступность**: семантическая разметка, `aria`-атрибуты, видимый фокус,
  `prefers-reduced-motion`, горячие клавиши (`Ctrl/Cmd+K` — поиск, `Esc` — закрыть).
- **Печать**: отдельные стили — меню и панели скрываются, остаётся документ.

## Проверка

Интерфейс прогоняется в jsdom против работающего сервера: страница берётся
из Django-шаблона, данные — из REST API.

| Что проверяется | Объём |
|---|---|
| Отрисовка всех разделов под всеми ролями | 45 экранов × 6 ролей = 270 |
| Вкладки, карточки объектов, формы создания | 25 вкладок, 13 карточек, 41 форма |
| CRUD через API: создание, изменение, удаление | сверка с ответом сервера |
| Права: запись в запрещённый раздел | ожидается 403 и откат в кэше |

Серверная часть покрыта Django-тестами: `python manage.py test apps.api`.
